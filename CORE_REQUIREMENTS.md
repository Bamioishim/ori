# ORI core requirements (from Bamio, Nov 5 2026)

Canonical list of product requirements. Status is honest: IMPLEMENTED (code + mocked/unit tests, not verified with real wallets or on-chain) / PARTIAL / OPEN / BLOCKED. Nothing here has been verified with a live signature or payment. See HANDOVER.md for blockers.

1. **Native Send & Receive** — every supported asset in the portfolio has direct Send and Receive to/from external blockchain wallets using real network addresses; the other side does not need ORI. Includes: copy address, paste address, network-aware address validation, network selection, fee estimates, transaction review, wallet authorization, transaction status and history.
   - NEAR Intents powers **cross-chain** operations only. Same-chain transfers are ordinary transfers (SOL → Solana wallet = normal Solana transaction; EVM → EVM = normal transfer). No cross-chain detour.
   - Unsupported signing must be shown as disabled, never as success.
   - Status — IMPLEMENTED (mocked tests only): Home Receive tile + Receive screen (real connected/added addresses, copy, network select, preferred currency); per-asset Send/Receive on Home (mobile rows + desktop table); Send screen with paste, network-aware validation, chain-RPC fee estimate, review, balance+fee+cap re-check right before signing, wallet signature, receipt-based status + history. Assets: ETH and USDC on Ethereum and Base (EIP-1193 wallet), SOL on Solana (Phantom `signAndSendTransaction`, @solana/web3.js SystemProgram transfer). All same-chain, no NEAR Intents.
   - OPEN: SPL tokens (e.g. Solana USDC/USDT), other EVM chains, NEAR (no NEAR wallet connector; shown as unavailable, never simulated).
2. **Gmail registration + emailed login code.** Status: IMPLEMENTED, BLOCKED in production. Registration and login both require a one-time Gmail code; no account is created without a verified `register` code; guest mode stays. Codes are one-time (replay-protected), expire in 10 min, 5 verify attempts, send rate limits per email and IP. These protections need a **durable server store** (`api/auth/_store.ts` `AuthStore`); none is configured, so the endpoints fail closed (503) until Bamio picks/approves one (e.g. a KV/Redis/DB). Gmail OAuth2 delivery is also unverified. Profiles stay device-local: no cross-device restore and no global username registry. Log out keeps the profile on the device and never touches wallets.
3. **Profile control on Home** replaces the EVM address above the portfolio (profile, account, log out) — DONE.
4. **Swaps on all actually supported chains/tokens**, discovered dynamically from the provider; a route is only executable when ORI can sign on that network. Status: IMPLEMENTED for quotes: the Swap screen lists every token in the live public `/v0/tokens` catalog (215 tokens, ~40 chains on Nov 5), marks non-signable origins "quote only"; the server validates every quote against the trusted catalog, executable-origin adapters (ETH/ERC-20 on Ethereum+Base, native SOL) and per-chain address formats. Swap confirmation is still a simulation; live swap execution is OPEN.
5. **Fees:** no app-added fee (quote sets no `appFees`); show network/provider fee and output separately; same-chain uses direct transfer. No invented gas targets. The 1Click JWT stays server-side; the unauthenticated (+0.25%) fallback needs Bamio's decision. Status: PARTIAL — Send shows the chain's network fee (gas × gas price / Solana fee per signature) and states ORI adds no fee; swap quote shows provider fee/spread separately.
6. **Quote settlement time** comes from `quote.timeEstimate` (seconds after deposit confirms); missing → "Time unavailable"; latest request wins; refresh every 30 s. Status: DONE (live response not re-traced: 1Click dry quotes were timing out on Nov 5).
7. **Spending-limit enforcement disclosure** — limits are checked in the ORI browser app only (cards + signing boundary, fail-closed); no backend, NEAR contract or Chain Signatures enforcement; external wallets are not governed. Status: DONE (disclosed + tests).
8. **Hey ORI is click activation only** (product doc v2). Status: DONE.


## Update 2026-11-05 (live swap execution + SPL)
- **Swap execution: IMPLEMENTED (mocked tests only).** Live mode (VITE_ORI_SETTLEMENT_MODE=live) fetches a server dry:false quote at review with the user's own source wallet as refundTo and own destination wallet as recipient. `checkSwapQuote` binds route, amountIn, recipient, refund, minAmountOut (≥99.5% of reviewed), deposit-address format for the origin chain, a deadline more than 30 s away, and no memo. Limits and the account are re-checked, then one direct deposit is made (native, ERC-20 `transfer`, or SPL `transferChecked`). It never uses approvals. /api/status is polled, and history goes to completed only on provider SUCCESS; REFUNDED, FAILED and pending stay as they are. A wallet refusal marks the entry cancelled.
- Example mode (settlement off) still simulates, and the sheet and receipt are labelled "EXAMPLE · SIMULATED". Quote-only origins are blocked ("Quote only · ORI cannot sign this deposit").
- **SPL USDC/USDT Send on Solana: IMPLEMENTED (mocked tests only).** Uses @solana/spl-token with pinned mints (USDC EPjF…Dt1v, USDT Es9v…NYB, 6 decimals). The swap origin also needs the catalog symbol and decimals to match. The recipient ATA is created idempotently only when missing, and the rent (getMinimumBalanceForRentExemption(165)) plus the network fee are shown in review. Other SPL mints are quote-only.
- **NOT verified live:** no real 1Click dry:false response, status response, wallet signature or on-chain transfer has been exercised. 1Click dry quotes were timing out server-side on Nov 5.
- **BLOCKED: durable AuthStore (Redis) + signed session.** Not done in this chunk. It needs a provisioned store and a server session secret (owner decision). The Gmail-code endpoints still fail closed with 503.
